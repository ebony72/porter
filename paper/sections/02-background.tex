\section{Model, Primitives, and Problem Formulation}
\label{sec:background}

\subsection{Quantum Circuits and Routing}
\label{sec:qcircuits}

Our input circuits act on $n$ logical qubits and use the gate basis
$\{\texttt{id},\texttt{rz},\texttt{sx},\texttt{x},\texttt{cx}\}$ produced
by Qiskit's optimization level~3 for MQT-Bench circuits
\cite{quetschlich2023mqtbench}. Thus, the two-qubit operations considered
by the router are controlled-NOT (CX) gates. We represent a circuit as a
directed acyclic graph (DAG) with an edge between consecutive gates on
each logical qubit. The \emph{front} is the set of unexecuted gates whose
predecessors have all executed. Only front gates may execute immediately or
be routed toward execution.

The physical qubits are partitioned into \emph{cores}. Each core has an
intra-core coupling graph, and adjacent cores are connected by an
inter-core link whose endpoints are \emph{communication ports}. In every
architecture evaluated here, adjacent cores have exactly one link, and each
core uses a distinct port for each neighbour. Hence, once an adjacent pair
of cores is chosen, the communication-port pair is fixed, and a
plan has no port to choose.

A \emph{layout} $\ell$ maps each logical qubit to a physical position. A
CX gate is \emph{local} when its operands are in the same core and
\emph{remote} otherwise. A local CX whose physical operands are not
adjacent in the coupling graph requires intra-core SWAPs. A remote CX
requires an inter-core communication primitive, possibly preceded by local
SWAPs that make the primitive ready. We write $\kappa_\ell(q)$ for the core
that holds logical qubit $q$ under $\ell$, $\dL(c,p,p')$ for the shortest-path distance between positions $p$ and $p'$ in core $c$, and $\dC(c,c')$
for the shortest-path distance between cores $c$ and $c'$ in the core graph.

\subsection{Objective, Scope, and Assumptions}
\label{sec:scope}

\textbf{Objective.} Given a circuit DAG $C$ on $n$ logical qubits, a
multi-core architecture $\arch$ with $K$ cores, intra-core coupling graphs,
inter-core links, designated communication ports, and an initial layout
$\ell_0$, the compiler must emit a legal operation stream that implements
every gate in $C$. The objective is to minimise the number of consumed
Einstein--Podolsky--Rosen (EPR) pairs. We record intra-core SWAP count,
circuit depth, and compile time, but no decision rule in this paper trades
these quantities against EPR-pair consumption.

\textbf{Cost model.} Each \TeleData{}, \TeleGate{}, and
\TeleGatePacket{} operation consumes one EPR pair. A packet consumes one
pair regardless of the number of remote CX gates that it contains; a
multi-hop \TeleData{} relocation consumes one pair for each hop. All links
have the same EPR-pair cost. This common unit permits comparison with
\TeleSABRE{}~\cite{russo2025telesabre} and \dSABRE{}~\cite{lidsabre}.

Communication ports are ordinary physical qubits. A port is occupied for
the duration of an inter-core operation and is available otherwise; we do
not assume dedicated communication memory. The model does not represent
link contention, entanglement-generation latency or fidelity, purification,
or classical-communication latency. Accordingly, all results concern
EPR-pair consumption under this model, rather than scheduled execution
time or end-to-end fidelity. \appThreats{} discusses these and the other
evaluation assumptions.

\textbf{State teleportation (\TeleData{}).} \TeleData{} moves a logical
qubit from a source communication port to a free destination port in an
adjacent core. It consumes one EPR pair. The relocated qubit may then meet
subsequent operands in its new core, making their gates local. Its benefit
is therefore \emph{latent}: one communication action can reduce the cost of
multiple later interactions.

\textbf{Gate teleportation (\TeleGate{}).} \TeleGate{} implements one
remote CX without moving either logical operand. An EPR pair entangles the
communication ports. A cat-entangler creates the cat state
$\alpha|00\rangle + \beta|11\rangle$ between control $q_c$ and the
remote target-side port $e_B$. A CX controlled by $e_B$ therefore acts as
if it were controlled by $q_c$; a cat-disentangler restores $q_c$ and
releases both ports. \appCatent{} gives the two constructions used here.
The benefit of \TeleGate{} is \emph{direct}: it discharges exactly one CX.

\textbf{Same-control packet (\TeleGatePacket{}).} If an ordered sequence
of remote CX gates has a common control and all of its targets are in the
same core, one cat-entangler/disentangler pair can bracket the sequence.
The ports remain reserved while each target is routed adjacent to $e_B$ and
its CX is executed. The sequence therefore consumes one EPR pair rather
than one pair per CX. This adapts AutoComm's communication-amortisation
idea~\cite{wu2022autocomm} to an online routing loop.

The primitives consequently differ in the respect that governs
scoring: how many CX gates one pair is spread over.
\TeleGate{} resolves one CX immediately, \TeleGatePacket{} resolves a
lookahead-discovered run whose length the compiler must discover, and
\TeleData{} changes the layout in anticipation
of future interactions. Section~\ref{sec:sfc-scoring} formalises this
comparison in the plan-scoring rule.
