\section{The \PORTER{} Compiler}
\label{sec:sfc}

Given a circuit and an initial layout $\ell_0$ (which \PORTER{} builds
itself, Section~\ref{sec:sfc-layout}), \PORTER{} repeats the \chg{loop of
Algorithm~\ref{alg:sfc}: drain what is executable, route local CX gates by
intra-core SWAPs, and otherwise commit to one inter-core \emph{plan},
prepare it, and execute it. Lines 11--19 are the plan-first remote stage
that distinguishes \PORTER{} from compilers deciding at single-action
granularity; \appExample{} walks through them on a concrete front where
they change the outcome. This section specifies one routing pass at a
fixed teleport-lookahead horizon $L_\mathrm{tp}$; \PORTER{}'s own protocol
routes at four candidate horizons and keeps the lowest-EPR result, which
invokes this loop repeatedly rather than changing it and is defined in}
Section~\ref{sec:horizon}.



\begin{algorithm}[t]
\caption{\PORTER{} \texttt{compile}$(C, \ell_0)$}
\label{alg:sfc}
\begin{algorithmic}[1]
\STATE $\ell \leftarrow \ell_0$; initialise DAG active and front sets from $C$
\WHILE{DAG has active gates}
  \STATE $F \leftarrow$ DAG front
  \STATE classify $F$ into singles, direct-local CX, local-CX-needing-SWAP,
         adjacent-remote CX, non-adjacent-remote CX \hfill\textit{(Sec.~\ref{sec:sfc-classify})}
  \IF{singles or direct-local CX present}
    \STATE execute them all; remove from DAG; \textbf{continue}
  \ENDIF
  \IF{local-CX-needing-SWAP present}
    \STATE generate candidate intra-core SWAPs, apply the best-scoring one
           (Eq.~\ref{eq:sfc-local}); \textbf{continue} \hfill\textit{(Sec.~\ref{sec:sfc-intra})}
  \ENDIF
  \STATE generate normal plans $\mathcal{P}$, blocked plans $\mathcal{B}$
         \hfill\textit{(Sec.~\ref{sec:sfc-plan-first})}
  \STATE score every plan in $\mathcal{P}\cup\mathcal{B}$
         \hfill\textit{(Sec.~\ref{sec:sfc-scoring})}
  \STATE $\pln{p}^{\ast} \leftarrow$ first plan of \chg{$\mathcal{P}$ in selection-key
         order ($\texttt{None}$ iff $\mathcal{P}=\emptyset$)}
  \IF{$\pln{p}^{\ast}$ is \texttt{None}}
    \STATE $\pln{p}^{\ast} \leftarrow$ best tail-relief plan seeded from $\mathcal{B}$
           \hfill\textit{(Sec.~\ref{sec:sfc-relief})}
  \ELSIF{$\mathcal{B}\neq\emptyset$ and
         $\max_{\pln{b}\in\mathcal{B}}\mathrm{total}(\pln{b})-\mathrm{total}(\pln{p}^{\ast})
          > m_\mathrm{assist}$}
    \STATE $\pln{b}^{\ast} \leftarrow \arg\max_{\pln{b}\in\mathcal{B}}\mathrm{total}(\pln{b})$
    \STATE $\pln{p}^{\ast} \leftarrow$ best relief plan for $\pln{b}^{\ast}$'s blocked core
           \hfill\textit{(Sec.~\ref{sec:sfc-relief})}
  \ENDIF
  \IF{$\pln{p}^{\ast}$ is \texttt{None}} \STATE \textbf{report deadlock; abort} \ENDIF
  \chg{\STATE apply preparation SWAPs until $\pln{p}^{\ast}$ is ready
         \hfill\textit{(Sec.~\ref{sec:sfc-plan-first})}
  \STATE execute $\pln{p}^{\ast}$}
\ENDWHILE
\RETURN emitted operations, final layout, stats
\end{algorithmic}
\end{algorithm}

\chg{The pseudocode suppresses the implementation's guards: the loop also
exits on an iteration budget or a no-progress limit, and preparation
detects a repeated decision state (Section~\ref{sec:sfc-progress}).}

\subsection{Initial Layout}
\label{sec:sfc-layout}

\PORTER{} routes from any \chg{layout the machine has spare capacity for
(Section~\ref{sec:sfc-progress}), and Section~\ref{sec:shared_results}
runs it on layouts built by other compilers. Left to itself it builds
$\ell_0$ with one deterministic heuristic --- no external partitioner, no
best-of-$N$ search --- giving every core at least $f_\mathrm{min}{=}2$
free positions. The floor is a requirement, not a tuned parameter: a core with no free position cannot vacate an occupied port, and one with a single free position cannot accept a \TeleData{}. \dSABRE{}~\cite{lidsabre} arrives at it independently. It plays three roles we keep apart --- this initial condition, the admission threshold a destination must meet \emph{before} a normal \TeleData{} (Section~\ref{sec:sfc-plan-first}), and the threshold defining a reservoir for relief (Section~\ref{sec:sfc-relief}) --- and it is not an invariant: a core admitted at exactly $f_\mathrm{min}$ drops to one free.}

\chg{The heuristic is temporal locality-greedy. Each CX $g=(q_i,q_j)$
contributes $\gamma^{\mathrm{asap}(g)}$, $\gamma{=}0.99$, to an
interaction weight $w(q_i,q_j)$, where $\mathrm{asap}(g)$ is its layer in
the CX-only DAG, so early interactions weigh more while repeated ones
accumulate. Logical qubits are visited in order of first appearance as a
CX operand and placed in the core holding the heaviest already-placed neighbour with headroom above $f_\mathrm{min}$; within a core, they go onto positions by descending weight onto ascending centrality. Its one weakness is a reservation uniform across cores, which suits a grid or
a ring but not a core graph with a hub (Section~\ref{sec:heavyhex}).}

\subsection{Front Classification}
\label{sec:sfc-classify}

\chg{Under layout $\ell$, a front CX $g=(q_i,q_j)$ sharing a core $c$ is \emph{direct-local} if $\dL(c,\ell(q_i),\ell(q_j))=1$ and \emph{local-needing-SWAP} otherwise; one spanning two cores is \emph{adjacent-remote} if they are core-graph neighbours and \emph{non-adjacent-remote} otherwise. 1Q gates are always executable. Executable gates drain first and completely, intra-core SWAPs next, and the remote stage is entered only once no front gate is intra-core.}

\subsection{Intra-Core SWAP Scoring}
\label{sec:sfc-intra}

This stage \chg{follows \SABRE{}'s local SWAP
scoring~\cite{li2019tackling}. For a local-needing-SWAP gate set
$F_\mathrm{loc}$, candidate SWAP edges are the coupling-graph neighbours
of every physical position $F_\mathrm{loc}$ touches, each scored under
its post-SWAP layout $\ell_a$ by}
\begin{equation}
  J(a) = \bar d_{\mathcal{F}}(a) + \lambda_\mathrm{loc}\,\bar d_{\mathcal{E}}(a),
  \qquad \lambda_\mathrm{loc}=0.8,
  \label{eq:sfc-local}
\end{equation}
the mean intra-core distance \chg{over $F_\mathrm{loc}$ plus the same mean
over an extended set of up to $N_\mathrm{loc}{=}20$ local CX gates from
the next $L_\mathrm{loc}{=}12$ DAG layers. The lowest $J$ is applied, ties breaking on raw front-layer distance then on a constant-seeded generator. Local candidates \emph{minimise} distance; remote plans \emph{maximise} gain.}

\subsection{Plan-First Remote Stage}
\label{sec:sfc-plan-first}

\chg{A \emph{plan} is one committable inter-core action across a single link:
which primitive fires, which gate or same-control run it discharges, and
between which pair of cores. It deliberately records no preparation-SWAP sequence, so plans answer \emph{what} remote work to do next --- each scored as if its preconditions were met --- and preparation answers \emph{how} to make the committed one executable.}

\chg{The primitive $\pi$ --- one of \TeleData{}, \TeleGate{} or \TeleGatePacket{} --- fixes the set $G(\pln{p})$ of gates discharged: the straddling front CX for a
\TeleGate{}, the collected same-control run for a \TeleGatePacket{}
(Section~\ref{sec:sfc-packet}), and the empty set for a \TeleData{},
whose value lies instead in the gates its relocation makes local
(Section~\ref{sec:sfc-scoring}). Source and destination are always
core-graph neighbours --- the \TeleGate{} family is generated only for a
core-adjacent CX, a \TeleData{} only for a one-hop move, and relief emits
a chain's last hop --- so every plan reserves exactly one link. A plan is fixed once generated, so commitment has a fixed object; readiness is a predicate on a plan and a layout, which preparation changes.}

\chg{Utility never includes readiness cost, so a plan that is merely cheap to prepare
cannot displace one buying more progress --- the property separating this scorer from \dSABRE{}'s, where staging cost is additive (Section~\ref{sec:related}). Once committed, \PORTER{} works only on that plan until it fires, a preparation SWAP having no meaning except relative to the plan it prepares. We adopt that \emph{commitment rule} structurally, not on measured grounds: no result in Section~\ref{sec:results} isolates it or the plan abstraction beneath it.}

\chg{\textbf{Candidate sets.} When the front holds only remote CX gates,
\textbf{normal plans} $\mathcal{P}$ are the actions that could fire once
prepared: for each adjacent-remote CX a \TeleGate{}, a
\TeleGatePacket{} if a same-control run of $\ge 2$ gates can be
collected, and for either endpoint a \TeleData{} into the partner's core
when that core has $f_\mathrm{min}$ free positions; a non-adjacent-remote CX contributes only \TeleData{} hops moving one endpoint \emph{strictly closer} to the other. \textbf{Blocked plans} $\mathcal{B}$ are the \TeleData{} candidates whose destination fails that test. \PORTER{} never commits one, but scores them as a measure of what capacity is costing, which is what the relief tiers act on.}

\chg{\textbf{Selection and preparation.} \PORTER{} walks $\mathcal{P}$ in the order of key~\eqref{eq:sfc-key} and commits to the first plan, subject to override by either relief tier (Section~\ref{sec:sfc-relief}). No admissibility test is needed: a ready plan fires immediately, and every unready one is preparable.}

\chg{A committed plan has two readiness requirements, one per side, and its
sides lie in different cores: source and destination for \TeleData{},
control and target for the \TeleGate{} family, whose remaining targets
are routed at execution time. A side is satisfied when its communication
port is free and, where that side carries a logical endpoint, that
endpoint sits adjacent to the port. So $\mathrm{ready}$ is both sides satisfied plus the $f_\mathrm{min}$ admission test for a \TeleData{}, and $\mathrm{prep}$ is the intra-core distance still to be closed --- zero exactly when the plan is ready, which is what tells commitment when to fire. Candidates for an unmet requirement are the edges incident to the endpoint, or to a nearest free position
tied for minimum distance to an occupied port; each is scored by
post-SWAP readiness cost, and at most one SWAP per side is applied per
pass.}

\chg{Preparation always completes. Routing never fills a core
(Section~\ref{sec:sfc-progress}), so with cores internally connected a
free position can always be walked to an occupied port to clear it, and
the endpoint then walked to a neighbour of that port along a path meeting
no edge incident to it --- at most a core diameter of local SWAPs
apiece. Neither side can undo the other, since the two lie in different
cores and a local SWAP moves no qubit between cores, which also leaves
the admission test intact. Algorithm~\ref{alg:sfc} therefore needs no
abandonment branch and no ready-or-preparable filter on selection.}

\subsection{Plan Scoring and the Selection Key}
\label{sec:sfc-scoring}

\chg{Scored plans are ordered by one lexicographic key, smallest first:}
\begin{equation}
  \mathrm{key}(\pln{p}) = \bigl(
     -\mathrm{total},\,
      \mathrm{prep},\,
     -f_\mathrm{dst}\bigr),
  \label{eq:sfc-key}
\end{equation}
each component evaluated at $\pln{p}$, with a stable plan identifier
resolving anything still tied. \chg{Here $f_\mathrm{dst}$ is the free capacity
of a \TeleData{}'s destination core, and is zero by convention for the
\TeleGate{} family, which consumes no destination slot.}

\chg{$\mathrm{total}$, the estimated gate progress the plan buys, decides
almost every comparison; the other two only break ties. It ranks rather
than measures: the \TeleGate{} family counts CX gates discharged outright
while a \TeleData{} is valued by reductions in core distance, and nothing
here establishes that the two are commensurate
(Section~\ref{sec:discussion}). $\mathrm{prep}$ orders plans of equal value by the local work each still needs. $-f_\mathrm{dst}$ prefers the \TeleData{} leaving more headroom and, since only a teleport scores here at all, prefers any teleport to a \TeleGate{}-family plan of equal value --- relocating a qubit being judged worth more than discharging one straddling gate, since the pair it spends makes every later CX with a partner in that core local. \appTables{} reports how often each
component decides.}

\chg{Two primitives score work performed outright: a \TeleGate{} scores $1$,
and a \TeleGatePacket{} the number of straddling gates in its collected
run, every member executing once the cat resource is live
(Section~\ref{sec:sfc-packet}). A \TeleData{} executes no gate, so its
score estimates the gates its moving qubit $q$ will meet once relocated.
Write $\kappa$ and $\kappa'$ for the maps sending a logical qubit to its
core before and after the move; for a CX $g=(q_i,q_j)$,}
\begin{equation}
  \Delta(g) = \dC\bigl(\kappa(q_i),\kappa(q_j)\bigr)
            - \dC\bigl(\kappa'(q_i),\kappa'(q_j)\bigr)
\end{equation}
is the core-graph distance the move removes from \chg{$g$, and
$\Delta(g)\in\{1,0,-1\}$ since the move is one hop.}

Three \chg{\emph{disjoint} sets of CX gates on $q$ contribute, obtained by
simulating the DAG frontier forward under $\kappa'$, each stage given what the earlier ones counted so no gate is summed twice. $D(\pln{p})$
is the front CX on $q$ --- the plan's seed and nothing else, a qubit
having at most one front gate at a time. $L(\pln{p})$ is reached by \emph{local closure}, the simulator retiring every front gate executable under $\kappa'$ until none is; these are current pressure rather than prediction. $A_k(\pln{p})$ holds gates found past that stopping front, in simulated layer $k \le L_\mathrm{tp}$, discounted by $w_k = \max(w_\mathrm{min}, w_0\gamma^{k-1})$, $w_0{=}0.9$, $\gamma{=}0.9$, $w_\mathrm{min}{=}0.5$. Depth counts DAG layers, so the companion cap $N_\mathrm{tp}{=}50$ cannot bind while $N_\mathrm{tp}\ge L_\mathrm{tp}$, a qubit contributing at most one gate per layer (\appTables{}); $L_\mathrm{tp}$ is the one
parameter \PORTER{} does not fix by constant
(Section~\ref{sec:horizon}). Only here does the score split, into a
realised part and a discounted one:}
\begin{align}
  \mathrm{direct}(\pln{p})    &= \!\!\!\!\sum_{g\in D(\pln{p})\cup L(\pln{p})}\!\!\!\!\Delta(g),
    \\[-2pt]
  \mathrm{lookahead}(\pln{p}) &= \sum_{k=1}^{L_\mathrm{tp}}\ \sum_{g\in A_k(\pln{p})} w_k\,\Delta(g),
    \nonumber
\end{align}
\chg{with $\mathrm{total} = \mathrm{direct} + \mathrm{lookahead}$, so
$L(\pln{p})$ enters at full weight alongside $D(\pln{p})$ and only}
$A_k(\pln{p})$ is discounted.

\subsection{Same-Control Packet Collection}
\label{sec:sfc-packet}

Same-control CX gates are chained by DAG dependency edges, so \chg{they never
appear in the front together: a packet must be collected by forward
simulation. From a seed adjacent-remote CX $g=(q_c,q_t)$ with target core
$c_t$, \PORTER{} simulates the frontier forward for up to $120$ layers,
absorbing any front CX sharing control $q_c$ with its target in $c_t$ (up to $8$ gates) and any front 1Q gate whose qubit is already in $c_t$, stopping at the first unproductive layer or at the size cap. The window counts layers rather than gates, so it is a cost guard rather than a tuning knob. One heuristic here is unablated:
stopping at the first unproductive layer can miss a packet separated by
harmless intervening work.}

\chg{What the plan is then ready for is opening the cat resource --- control
beside the control-side port, both ports free --- not the execution of
every member: the remaining targets are brought beside the target-side
port as the packet runs, by SWAPs barred from touching either live port.
The sequence is emitted in its collected order: one \texttt{cat\_entangler}, consuming the packet's single EPR pair; one \texttt{cat\_cx} per member; a closing \texttt{cat\_disentangler}. Fixing that order at collection time is what lets the scorer count every member as work the packet will do: DAG-chained members cannot become unexecutable once the resource is live.}

\subsection{Capacity Relief}
\label{sec:sfc-relief}

Both tiers answer the same question --- some core $c$ is at or below
$f_\mathrm{min}$ and a \TeleData{} wants to enter it --- by moving a
qubit \emph{out} of the congested region rather than into it. \chg{A
breadth-first search from $c$ finds the nearest \emph{reservoir}, a core
with at least $f_\mathrm{min}$ free positions, and the relief action moves one qubit from that path's penultimate core into the reservoir at its end. Candidates are scored by the plan machinery already described, grouped by hop count so shorter paths are tried first.}

\chg{What is committed is a single hop, not the path: control returns to the
top of Algorithm~\ref{alg:sfc}, which regenerates every plan, so a
two-hop path frees the intermediate core and only the next iteration
carries relief inwards. That granularity is what separates \PORTER{}'s
relief from an atomic relay (Section~\ref{sec:related}) and what lets the
opportunistic tier compete with ordinary work on the same scoring.}

The \chg{tiers run the same search and differ only in when they fire.
\textbf{Tail relief} fires reactively, when $\mathcal{P}$ is empty and
the front is starved; \textbf{opportunistic relief} pre-emptively, while
a normal plan is still available, whenever the best-scoring blocked plan
out-scores it by more than $m_\mathrm{assist}{=}5.0$. Either way what is
committed is a relief \TeleData{} generated for the purpose, never the
blocked plan itself.}

\subsection{Progress and the Failure Model}
\label{sec:sfc-progress}

Deterministic greedy routing on a capacity-constrained machine can stall,
and \PORTER{} layers four defences. It keeps capacity away from zero: a
core with no free position is terminal, so a \TeleData{} enters $c$ \chg{only while $\mathrm{free}(c)\ge f_\mathrm{min}$, leaving one behind. Routing therefore cannot create a terminal core, and a supplied layout containing one is legalised by an eviction into the core with most room --- a layout no core can receive that eviction from is the only input \PORTER{} refuses. It detects starvation, an empty $\mathcal{P}$
beside a non-empty $\mathcal{B}$ naming the cores responsible, and
manufactures capacity from that signal by tail relief
(Section~\ref{sec:sfc-relief}). And the implementation bounds every loop,}
hashing its decision state once per preparation round and raising if it
repeats, under \chg{an iteration budget and a no-progress limit --- safeguards
on the greedy realisation of the preparation policy, not conditions its
argument needs. Together these make every returned route correct and
every run terminating, but not every run successful, the guarantee \dSABRE{} has and \PORTER{} does not (Section~\ref{sec:related}). A per-iteration cost analysis is in
\appComplexity{}.}
