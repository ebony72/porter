\section{The \PORTER{} Compiler}
\label{sec:sfc}

Given a circuit and an initial layout $\ell_0$ (which \PORTER{} builds
itself, Section~\ref{sec:sfc-layout}), \PORTER{} repeats the following
loop (Algorithm~\ref{alg:sfc}) until every gate has been emitted, a
configurable iteration budget is exhausted, or a configurable number
of iterations passes with no gate retired --- a no-progress guard that
abandons a stalled route without waiting for the budget. Algorithm~\ref{alg:sfc}
charts the routing pass; lines 11--19 are the plan-first remote stage that
distinguishes \PORTER{} from compilers deciding at single-action
granularity, and \appExample{} walks through them on a concrete front
where they change the outcome. This section specifies one routing
pass, at a fixed teleport-lookahead horizon $L_\mathrm{tp}$. \PORTER{}'s
own protocol routes at \chg{four candidate horizons and keeps the lowest-EPR}
result; because that invokes this loop repeatedly rather than changing
it, it is defined with the other operating protocols in
Section~\ref{sec:horizon}.


\begin{algorithm}[t]
\caption{\PORTER{} \texttt{compile}$(C, \ell_0)$}
\label{alg:sfc}
\begin{algorithmic}[1]
\STATE $\ell \leftarrow \ell_0$; initialise DAG active and front sets from $C$
\WHILE{DAG has active gates}
  \STATE $F \leftarrow$ DAG front
  \STATE classify $F$ into singles, direct-local CX, local-CX-needing-SWAP,
         adjacent-remote CX, non-adjacent-remote CX \hfill\textit{(Sec.~\ref{sec:sfc-classify})}
  \IF{singles or direct-local CX present}
    \STATE execute them all; remove from DAG; \textbf{continue}
  \ENDIF
  \IF{local-CX-needing-SWAP present}
    \STATE generate candidate intra-core SWAPs, apply the best-scoring one
           (Eq.~\ref{eq:sfc-local}); \textbf{continue} \hfill\textit{(Sec.~\ref{sec:sfc-intra})}
  \ENDIF
  \STATE generate normal plans $\mathcal{P}$, blocked plans $\mathcal{B}$
         \hfill\textit{(Sec.~\ref{sec:sfc-plan-first})}
  \STATE score every plan in $\mathcal{P}\cup\mathcal{B}$
         \hfill\textit{(Sec.~\ref{sec:sfc-scoring})}
  \STATE $\pln{p}^{\ast} \leftarrow$ first plan of $\mathcal{P}$, in selection-key
         order, that is ready or admits an improving preparation SWAP
  \IF{$\pln{p}^{\ast}$ is \texttt{None}}
    \STATE $\pln{p}^{\ast} \leftarrow$ best tail-relief plan seeded from $\mathcal{B}$
           \hfill\textit{(Sec.~\ref{sec:sfc-relief})}
  \ELSIF{$\mathcal{B}\neq\emptyset$ and
         $\max_{\pln{b}\in\mathcal{B}}\mathrm{total}(\pln{b})-\mathrm{total}(\pln{p}^{\ast})
          > m_\mathrm{assist}$}
    \STATE $\pln{b}^{\ast} \leftarrow \arg\max_{\pln{b}\in\mathcal{B}}\mathrm{total}(\pln{b})$
    \STATE $\pln{p}^{\ast} \leftarrow$ best relief plan for $\pln{b}^{\ast}$'s blocked core
           \hfill\textit{(Sec.~\ref{sec:sfc-relief})}
  \ENDIF
  \IF{$\pln{p}^{\ast}$ is \texttt{None}} \STATE \textbf{report deadlock; abort} \ENDIF
  \WHILE{$\pln{p}^{\ast} \neq \texttt{None}$ and $\pln{p}^{\ast}$ not ready}
    \STATE $S \leftarrow$ improving preparation SWAPs for $\pln{p}^{\ast}$
           \hfill\textit{(Sec.~\ref{sec:sfc-prep})}
    \IF{$S = \emptyset$}
      \STATE $\pln{p}^{\ast} \leftarrow \texttt{None}$ \hfill\textit{(abandon)}
    \ELSIF{decision state $(\pln{p}^{\ast}, \ell, \mathrm{rng})$ seen before}
      \STATE \textbf{report preparation cycle; abort}
    \ELSE \STATE apply $S$
    \ENDIF
  \ENDWHILE
  \IF{$\pln{p}^{\ast} \neq \texttt{None}$} \STATE execute $\pln{p}^{\ast}$ \ENDIF
\ENDWHILE
\RETURN emitted operations, final layout, stats
\end{algorithmic}
\end{algorithm}

\subsection{Initial Layout}
\label{sec:sfc-layout}

\PORTER{} routes from any initial layout the machine has spare
capacity for (Section~\ref{sec:sfc-progress}, which also legalises a
supplied layout whose cores are full), and the shared- and
cross-layout experiments of Section~\ref{sec:shared_results} run it on
layouts built by other compilers. Left to itself it builds $\ell_0$ with
one deterministic heuristic --- no external partitioner, no best-of-$N$
search --- giving every core at least $f_\mathrm{min}{=}2$ free
positions.

That floor is a requirement rather than a tuned parameter, and
\dSABRE{}~\cite{lidsabre} independently arrives at the same value. A core
with no free position cannot vacate an occupied communication port by
local SWAPs, so nothing can reach it; a core with one free position
cannot accept a \TeleData{}, since the arriving qubit would fill it. Two
is the smallest reserve under which a core can both receive a teleport
and still make room afterwards. $f_\mathrm{min}$ accordingly plays three
roles, which we keep apart: this \emph{initial} condition; the
\emph{admission threshold} a destination must meet \emph{before} a normal
\TeleData{} (Section~\ref{sec:sfc-plan-first}); and the threshold
defining a \emph{reservoir} for relief (Section~\ref{sec:sfc-relief}). It
is not an invariant --- a core admitted at exactly $f_\mathrm{min}$ drops
to one free, and cores do reach one free position during routing.

\textbf{Temporal locality-greedy.} Three steps.
\emph{(i) Weighting}: each CX gate $g=(q_i,q_j)$ contributes
$\gamma^{\mathrm{asap}(g)}$ to the interaction weight $w(q_i,q_j)$, where
$\mathrm{asap}(g)$ is $g$'s as-soon-as-possible layer in the CX-only DAG and
$\gamma{=}0.99$, so early interactions weigh more than late ones while
repeated interactions accumulate. \emph{(ii) Core assignment}: logical
qubits are visited in the order they first appear as a CX operand and
each is placed in the core holding its heaviest already-placed
neighbour when that core has headroom above $f_\mathrm{min}$, falling
back to the core with the most remaining reserved capacity.
\emph{(iii) Physical placement}: within each core, logicals are laid
onto positions by descending interaction weight onto ascending
intra-core centrality, so the most-connected qubits take the most
central slots.

The steps are complementary. The discount co-locates the pairs that
must interact soonest; first-appearance order handles chain-structured
circuits, where a balanced-first-layer rule would scatter the chain
across cores; and the centrality step keeps hub qubits cheap to reach.
Its one weakness is that the $f_\mathrm{min}$ reservation is uniform
across cores, which suits a grid or a ring but not a core graph with a
hub (Section~\ref{sec:heavyhex}).

\subsection{Front Classification}
\label{sec:sfc-classify}

Every front gate is classified under the current layout $\ell$. 1Q
gates are always directly executable; a CX $g=(q_i,q_j)$ with both
operands in core $c$ is \emph{direct-local} if
$\dL(c,\ell(q_i),\ell(q_j))=1$ and \emph{local-needing-SWAP}
otherwise; a CX whose operands lie in different cores is
\emph{adjacent-remote} if those cores are core-graph neighbours and
\emph{non-adjacent-remote} otherwise. Directly executable gates drain
first and completely, intra-core SWAPs are exhausted next, and
remote-stage decisions are taken only once no front gate is
intra-core.

\subsection{Intra-Core SWAP Scoring}
\label{sec:sfc-intra}

This stage is \SABRE{}~\cite{li2019tackling}. For a local-needing-SWAP
gate set $F_\mathrm{loc}$, candidate SWAP edges are the coupling-graph
neighbours of every physical position $F_\mathrm{loc}$ touches, and each
is scored under its post-SWAP layout $\ell_a$ by
\begin{equation}
  J(a) = \bar d_{\mathcal{F}}(a) + \lambda_\mathrm{loc}\,\bar d_{\mathcal{E}}(a),
  \qquad \lambda_\mathrm{loc}=0.8,
  \label{eq:sfc-local}
\end{equation}
the mean intra-core distance $\dL(c,\ell_a(q_i),\ell_a(q_j))$ over
$F_\mathrm{loc}$, plus the same mean over an extended set of up to
$N_\mathrm{loc}{=}20$ local CX gates from the next $L_\mathrm{loc}{=}12$
DAG layers. The lowest $J$ is applied; ties break on raw front-layer
distance, then on a constant-seeded generator. Note the sign convention
differs between the two stages: local candidates \emph{minimise}
distance, whereas remote plans \emph{maximise} gain
(Section~\ref{sec:sfc-scoring}).

\subsection{Plan-First Remote Stage}
\label{sec:sfc-plan-first}

\PORTER{} manipulates remote work as \emph{plans}. A plan is a
complete, committable specification of one inter-core action: which
primitive fires, which gate or same-control run it resolves, its
direction, and consequently its \emph{readiness conditions} --- which
logical endpoint must sit adjacent to which communication port, and
which ports must be free. What it deliberately leaves unspecified is
the SWAP sequence that establishes those conditions. Alternatives are
compared at the level of \emph{what} remote work to do next, each
scored as if its preconditions were met; only the committed plan is
handed to the machinery that works out \emph{how}.

Formally, a plan is a tuple
\[
  \pln{p} \;=\; \bigl(\pi,\; \chg{g,\; G(\pln{p}),\; q,\; c_\mathrm{src},\;
                c_\mathrm{dst},\; \mathrm{mode},\; \Pi(\pln{p})\bigr),}
\]
with $\pi\in\{\TeleData{},\TeleGate{},\TeleGatePacket{}\}$ the primitive,
\chg{$g$ the front CX that seeds it, $q$ the qubit a \TeleData{} moves
($\bot$ for the \TeleGate{} family), $c_\mathrm{src}$ and $c_\mathrm{dst}$
the cores, $\mathrm{mode}$ the generating rule --- localise onto an adjacent
core, reduce distance by one hop, or relieve capacity --- and $\Pi(\pln{p})$
the inter-core link it reserves. The seed and the moving qubit are what
individuate a \TeleData{}: its $G(\pln{p})$ is empty, so without them two
plans moving different qubits between the same pair of cores would be the
same tuple. On the single-link interconnect assumed here $\Pi(\pln{p})$
follows from the two cores, and it becomes an independent choice exactly
when a core pair is joined by more than one link. Every field is static:}
a plan is fixed once generated, so commitment has a fixed object. Readiness is not a field but a predicate derived from a plan and
a layout, $\mathrm{ready}(\pln{p},\ell)$, holding when $\pln{p}$ can fire
under $\ell$; preparation changes $\ell$ and so changes the predicate, never
the plan.
$G(\pln{p})$ is the set of gates it \emph{discharges}: for a \TeleGate{}
the single front CX; for a \TeleGatePacket{} the collected same-control
run (Section~\ref{sec:sfc-packet}); for a \TeleData{} the empty set,
since moving a qubit executes no gate --- its value lies in the gates the
relocation makes local, which the scorer estimates
(Section~\ref{sec:sfc-scoring}).

Three quantities are kept distinct: the plan's \emph{utility}, evaluated
under the hypothesis that $\mathrm{ready}(\pln{p},\ell)$ holds whether or
not it does; its \emph{readiness cost}, the local work still needed, used
only to break ties; and the \emph{preparation policy} that chooses those
local SWAPs after $\pln{p}$ is committed. Two design decisions follow:
utility never includes readiness cost, and once a plan is committed
\PORTER{} works only on that plan --- it generates no other plan and
scores no alternative --- until the plan fires or is abandoned because its
preparation policy offers no move.

The second is the \emph{commitment rule}, and we adopt it on structural
grounds rather than measured ones. A preparation SWAP has no meaning
except relative to the plan it prepares, so a router that reopens the
choice part-way through preparation can leave the layout carrying moves
made towards an action it then abandons; committing makes preparation and
the action it serves one unit, and gives the abandonment test below
--- no local SWAP on an unsatisfied side serves the plan --- something
well defined to fire on. It also
fixes the granularity at which the plan set is derived --- once per
committed action rather than once per router iteration. What it does
\emph{not} come with is an experiment: no result in
Section~\ref{sec:results} isolates either the commitment rule or the
plan abstraction beneath it, so no reduction reported there is attributed
to them; separating their share would need a hop-granular candidate set,
which is a different router.

\textbf{The candidate sets.} When the front holds only remote CX gates,
\PORTER{} builds two sets. \textbf{Normal plans} $\mathcal{P}$ are the
actions that could fire once prepared. For each adjacent-remote CX they
hold a \TeleGate{}; a \TeleGatePacket{} if a same-control run of $\ge 2$
gates can be collected; and, for either endpoint, a \TeleData{} into the
partner's core when that core has $f_\mathrm{min}$ free positions. A
non-adjacent-remote CX cannot be discharged in one action, so it
contributes only \TeleData{} hops that move one endpoint to a neighbouring
core \emph{strictly closer} to the other endpoint's core, again subject to
$f_\mathrm{min}$.

\textbf{Blocked plans} $\mathcal{B}$ are the same \TeleData{} candidates
whose destination fails the $f_\mathrm{min}$ test. \PORTER{} never
commits one --- executing it would drive a core below the floor. It scores
them anyway, as a measurement of what capacity is currently costing:
$\mathcal{B}$ names the cores that are saturated and says how much gain
is being forgone there, which is what the relief tiers of
Section~\ref{sec:sfc-relief} act on.

\textbf{Selection.} Every plan in both sets is scored before any
preparation SWAP for it exists; Section~\ref{sec:sfc-scoring} gives the
score and the ordering key~\eqref{eq:sfc-key} it induces. \PORTER{} then walks $\mathcal{P}$ in that
order and commits to the first plan it can actually work on. A plan
qualifies if it is \emph{ready} --- its endpoints already sit beside the
ports it needs and those ports are free, so it can fire immediately --- or
if it is \emph{preparable}: not ready, but some local SWAP moves the
layout strictly closer to readiness. A higher-scoring plan that is neither is skipped rather than waited for,
and such plans do occur --- typically a side whose core is full, where no
local SWAP can change the free-slot count or clear a port, so no
preparation will ever make the plan fire.

Two things can override the choice, and both are driven by the single
best-scoring member of $\mathcal{B}$ alone --- call it $\pln{b}^{\ast}$;
the rest of $\mathcal{B}$ enters no comparison. If a plan was selected but
$\pln{b}^{\ast}$ out-scores it by more than $m_\mathrm{assist}{=}5.0$,
\PORTER{} drops the selected plan and relieves the core blocking
$\pln{b}^{\ast}$ instead. If nothing in $\mathcal{P}$ was ready or
preparable --- which includes $\mathcal{P}=\emptyset$ but is not limited
to it --- it relieves $\mathcal{B}$'s blocked destinations in ascending
hop order, taking the highest-scoring blocked plan among those at the
smallest hop count as the seed. In both cases what is committed is a relief \TeleData{}
generated for the purpose, never $\pln{b}^{\ast}$ itself. Having
committed, \PORTER{} applies only that plan's preparation SWAPs, and
leaves that loop three ways (Algorithm~\ref{alg:sfc}, lines 23--35):
ready, and it executes; no improving SWAP, and it is abandoned to the top of
the outer loop; or the decision state --- plan, layout, RNG --- repeats,
which raises rather than loops. Abandonment needs no exclusion list, since
selection admits only plans that are ready or admit an improving SWAP, a
test the abandoned plan cannot pass again until the layout moves.

\textbf{Preparation SWAPs.}\label{sec:sfc-prep} A committed plan has
exactly two readiness requirements, one per side: source and destination
for \TeleData{}, control and target for \TeleGate{} and
\TeleGatePacket{}, whose target side is routed at execution time
(Section~\ref{sec:sfc-packet}). For each unmet requirement, candidate
SWAPs are the edges incident to the plan's logical endpoint, or to a
nearest free position tied for minimum distance to the relevant port
while that port stays occupied. Each is scored by the post-SWAP
readiness cost, and at most one improving SWAP per side is applied per
pass.

\subsection{Plan Scoring and the Selection Key}
\label{sec:sfc-scoring}

Every candidate is scored before any preparation SWAP for it exists, and
the scored plans are ordered by one lexicographic key, smallest first:
\begin{equation}
  \mathrm{key}(\pln{p}) = \bigl(
     -\mathrm{total},\,
      \mathrm{prep},\,
     -f_\mathrm{dst}\bigr),
  \label{eq:sfc-key}
\end{equation}
each component evaluated at $\pln{p}$, with a stable plan identifier
resolving anything still tied. The order is the design, so we take the
components in turn.

\textbf{$\mathrm{total}$} is the estimated gate progress the plan buys,
negated so that more progress sorts first. It decides almost every
comparison; the two components after it only break ties. Preparation
cost is not part of it, so a plan that happens to be cheap to prepare
cannot displace one that buys more progress --- the property that
separates this scorer from \dSABRE{}'s, where staging cost is additive
(Section~\ref{sec:related}).

\textbf{$\mathrm{prep}$} is the readiness cost --- how far the current
layout is from satisfying the $\mathrm{ready}$ predicate of
Section~\ref{sec:sfc-plan-first}, measured as intra-core distance from
each endpoint to the port it must reach. It is zero exactly when the
plan is ready, so it subsumes readiness itself: among plans of equal
value, one that can fire now precedes one that cannot, and two unready
plans are ordered by how much local work each still needs.

\textbf{$-f_\mathrm{dst}$} is the free capacity of the destination core,
negated, so between plans of equal value and preparation cost the one
leaving more room wins. Only a \TeleData{} consumes a destination slot;
every other primitive scores zero here, so this component also carries a
preference for the plan that improves the layout. It is computed
alongside the score, never added to it.

\chg{ A \TeleGate{} scores $\mathrm{total}{=}1$ and a}
\TeleGatePacket{} is only generated carrying at least two straddling
gates, so $-\mathrm{total}$ always separates those two primitives and
only the \TeleData{}-first half of a plan-kind ordering was ever
reachable; $-f_\mathrm{dst}$ now carries it. And since $\mathrm{total}$
is the sum of the realised and discounted gains, a trailing
$-\mathrm{lookahead}$ could separate two plans only where those two parts
traded in exactly compensating amounts --- once in $24{,}494$ rankings
over the benchmark suites, where it preferred the plan with the
\emph{smaller} realised gain. Removing all three leaves the emitted
circuit bit-for-bit identical on every instance but two.

That leaves $\mathrm{total}$, which the rest of this subsection computes,
taking the three primitives in turn.

Two of them are counts of work the action performs outright. A
\textbf{\TeleGate{}} scores $1$: the one straddling gate it executes,
with nothing left over. A \textbf{\TeleGatePacket{}} scores the number of
straddling gates in its collected run, also with nothing left over, since
collection returns a committed executable sequence and every member of it
executes once the cat resource is live (Section~\ref{sec:sfc-packet}).

A \textbf{\TeleData{}} executes no gate at all. Its score has to estimate
the gates its moving qubit $q$ will meet once relocated, which needs a
measure of how much a move brings a gate closer to being executable.

\textbf{Gate progress.} Write $\kappa$ for the map sending a logical
qubit to the core holding it under the current layout, and $\kappa'$ for
the same map after the move --- identical to $\kappa$ except that $q$ now
sits in $c_\mathrm{dst}$. For a CX $g=(q_i,q_j)$,
\begin{equation}
  \Delta(g) = \dC\bigl(\kappa(q_i),\kappa(q_j)\bigr)
            - \dC\bigl(\kappa'(q_i),\kappa'(q_j)\bigr)
\end{equation}
is the core-graph distance the move removes from $g$. A \TeleData{} moves
one qubit one hop, so $\Delta(g)\in\{1,0,-1\}$: $1$ when the hop brings
$g$'s operands a core closer, whether or not that makes them local; $0$
when it does not touch $g$; $-1$ when it pushes them apart.

Three sets of CX gates on $q$
contribute, obtained by simulating the DAG frontier forward under
$\kappa'$:
\begin{itemize}[leftmargin=1.2em,itemsep=1pt,topsep=2pt]
\item $D(\pln{p})$, the front CX on $q$ --- by the same one-gate-per-qubit
  fact, the plan's seed gate and nothing else, so
  $\lvert D(\pln{p})\rvert = 1$.
\item $L(\pln{p})$, the CX gates on $q$ reached by \emph{local closure}.
  The simulator repeatedly retires every front gate executable under
  $\kappa'$ --- one-qubit gates, and CX gates $\kappa'$ places in one core
  --- advancing the front and exposing gates blocked behind them. Every CX
  on $q$ appearing in any front along the way joins $L(\pln{p})$, and
  closure stops at the first front with nothing locally executable. These
  are current pressure rather than prediction: reaching them needs no gate
  outside $\kappa'$'s reach.
\item $A_k(\pln{p})$, the CX gates on $q$ found by continuing past that
  stopping front, in simulated layer $k \le L_\mathrm{tp}$, discounted by
  $w_k = \max(w_\mathrm{min}, w_0\gamma^{k-1})$ with $w_0{=}0.9$,
  $\gamma{=}0.9$, $w_\mathrm{min}{=}0.5$. These are prediction. The depth
  $L_\mathrm{tp}$ is counted in DAG layers; a companion cap
  $N_\mathrm{tp}$ on the gate count cannot bind while
  $N_\mathrm{tp}\ge L_\mathrm{tp}$, since a qubit contributes at most one
  gate per layer (\appTables{}). $L_\mathrm{tp}$ is the one parameter
  \PORTER{} does not fix by constant (Section~\ref{sec:horizon}).
\end{itemize}
Only here does the score split, into a certain part and a discounted one:
$\mathrm{total} = \mathrm{direct} + \mathrm{lookahead}$, where
\begin{align}
  \mathrm{direct}(\pln{p})    &= \!\!\!\!\sum_{g\in D(\pln{p})\cup L(\pln{p})}\!\!\!\!\Delta(g),
    \\[-2pt]
  \mathrm{lookahead}(\pln{p}) &= \sum_{k\ge1}\ \sum_{g\in A_k(\pln{p})} w_k\,\Delta(g).
    \nonumber
\end{align}
So $L(\pln{p})$ enters at full weight alongside $D(\pln{p})$, and only
$A_k(\pln{p})$ is discounted.

\subsection{Same-Control Packet Collection}
\label{sec:sfc-packet}

Same-control CX gates are chained by DAG dependency edges, so they
never appear in the front together: a packet cannot be read off the
front and must be collected by forward simulation.
From a seed adjacent-remote CX $g=(q_c,q_t)$ with target core $c_t$,
\PORTER{} simulates the DAG frontier forward for up to $120$ layers,
absorbing any front CX that shares control $q_c$ and has its target in
$c_t$ (up to $8$ gates), and any front 1Q gate whose qubit is already in
$c_t$, since those execute freely while the cat resource is live.
Collection stops at the first unproductive layer or at the size cap. The
window counts simulated layers rather than collected CXs, so it is a cost
guard rather than a tuning knob, and because the simulation reaches past
the current front a packet may contain gates a front-only scan could
not. One heuristic here is unablated: stopping at the first unproductive
layer can miss a packet separated by harmless intervening work.

Collection only \emph{discovers} the run; nothing is emitted while it
simulates. The sequence is recorded on the plan and, if that plan is
committed, emitted in exactly that order --- one \texttt{cat\_entangler},
consuming the packet's single EPR pair; one \texttt{cat\_cx} per member,
each target first brought beside the port by local SWAPs that may not
touch either live port; and a closing \texttt{cat\_disentangler} freeing
both. Fixing the order at collection time is what lets the scorer count
every member as work the packet will do: the members are DAG-chained, so
that order respects their dependencies and none can become unexecutable
once the resource is live.

\subsection{Capacity Relief}
\label{sec:sfc-relief}

Both tiers answer the same question --- some core $c$ is at or below
$f_\mathrm{min}$ and a \TeleData{} wants to enter it --- by moving a
qubit \emph{out} of the congested region rather than into it. Neither
picks a destination freely: a breadth-first search from $c$ over the core
graph finds the nearest \emph{reservoir}, a core with at least
$f_\mathrm{min}$ free positions, and the relief action moves one qubit
from the penultimate core of that path into the reservoir at its end.
Every logical qubit in the penultimate core is a candidate, scored and
ordered by the plan machinery already described and grouped by hop count
so shorter paths are tried first. Chaining beyond one hop is on by
default, letting relief propagate when the immediate neighbour is itself
full.

The two tiers differ only in when they fire. \textbf{Tail relief} fires
reactively, when $\mathcal{P}$ is empty and the front is starved.
\textbf{Opportunistic relief} fires pre-emptively, while a normal plan is
still available, whenever a blocked plan out-scores it by more than
$m_\mathrm{assist}$ --- the judgement being that clearing the congestion
now is worth more than taking the best currently legal action.

\subsection{Progress and the Failure Model}
\label{sec:sfc-progress}

Deterministic greedy routing on a capacity-constrained machine can stall,
and \PORTER{} layers four defences. It keeps capacity away from zero: a
core with no free position is terminal, so a \TeleData{} enters $c$ only
while $\mathrm{free}(c)\ge f_\mathrm{min}$, leaving one position behind.
Routing therefore cannot create a terminal core, and a supplied layout
containing one is legalised first by evicting a qubit into the core with
most room --- the only input \PORTER{} refuses is one where no core can
receive that eviction. It detects starvation rather than thrashing, an
empty $\mathcal{P}$ beside a non-empty $\mathcal{B}$ naming the cores
responsible. It manufactures capacity, tail relief turning that signal
into work (Section~\ref{sec:sfc-relief}). And it bounds every loop,
hashing its decision state once per preparation round and raising if it
repeats, under two budgets. Together these make every returned route
correct and every run terminating, but not every run successful ---
the guarantee \dSABRE{} has and \PORTER{} does not
(Section~\ref{sec:related}). A
per-iteration cost analysis is in \appComplexity{}.
