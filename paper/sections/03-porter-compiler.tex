\section{The \PORTER{} Compiler}
\label{sec:sfc}

Given a circuit and an initial layout $\ell_0$ (which \PORTER{} builds
itself, Section~\ref{sec:sfc-layout}), \PORTER{} repeats the following
loop (Algorithm~\ref{alg:sfc}) until every gate has been emitted or a
configurable iteration budget is exhausted. Algorithm~\ref{alg:sfc}
charts one iteration; lines 11--19 are the plan-first remote stage that
distinguishes \PORTER{} from compilers deciding at single-action
granularity, and \appExample{} walks through them on a concrete front
where they change the outcome.


\begin{algorithm}[t]
\caption{\PORTER{} \texttt{compile}$(C, \ell_0)$}
\label{alg:sfc}
\begin{algorithmic}[1]
\STATE $\ell \leftarrow \ell_0$; initialise DAG active/frontier sets from $C$
\WHILE{DAG has active gates}
  \STATE $F \leftarrow$ DAG front (bounded by \texttt{dag\_front\_limit})
  \STATE classify $F$ into singles, direct-local CX, local-CX-needing-SWAP,
         adjacent-remote CX, non-adjacent-remote CX \hfill\textit{(Sec.~\ref{sec:sfc-classify})}
  \IF{singles or direct-local CX present}
    \STATE execute them all; remove from DAG; \textbf{continue}
  \ENDIF
  \IF{local-CX-needing-SWAP present}
    \STATE generate candidate intra-core SWAPs, apply the best-scoring one
           (Eq.~\ref{eq:sfc-local}); \textbf{continue} \hfill\textit{(Sec.~\ref{sec:sfc-intra})}
  \ENDIF
  \STATE generate normal plans $\mathcal{P}$, blocked plans $\mathcal{B}$
         \hfill\textit{(Sec.~\ref{sec:sfc-plan-first})}
  \STATE score every plan in $\mathcal{P}\cup\mathcal{B}$
         \hfill\textit{(Sec.~\ref{sec:sfc-scoring})}
  \STATE $p^\ast \leftarrow$ first plan of $\mathcal{P}$, in selection-key
         order, that is ready or admits an improving preparation SWAP
  \IF{$p^\ast$ is \texttt{None}}
    \STATE $p^\ast \leftarrow$ best tail-relief plan seeded from $\mathcal{B}$
           \hfill\textit{(Sec.~\ref{sec:sfc-relief})}
  \ELSIF{$\mathcal{B}\neq\emptyset$ and
         $\max_{b\in\mathcal{B}}\mathrm{total}(b)-\mathrm{total}(p^\ast)
          > m_\mathrm{assist}$}
    \STATE $b^\ast \leftarrow \arg\max_{b\in\mathcal{B}}\mathrm{total}(b)$
    \STATE $p^\ast \leftarrow$ best relief plan for $b^\ast$'s blocked core
           \hfill\textit{(Sec.~\ref{sec:sfc-relief})}
  \ENDIF
  \IF{$p^\ast$ is \texttt{None}} \STATE \textbf{report deadlock; abort} \ENDIF
  \STATE apply $p^\ast$'s own preparation SWAPs until ready, then execute it
\ENDWHILE
\RETURN emitted operations, final layout, stats
\end{algorithmic}
\end{algorithm}

\subsection{Initial Layout}
\label{sec:sfc-layout}

\PORTER{} routes from any initial layout, and the shared- and
cross-layout experiments of Section~\ref{sec:shared_results} run it on
layouts built by other compilers. Left to itself it builds $\ell_0$ with
one deterministic heuristic --- no external partitioner, no best-of-$N$
search --- giving every core at least $f_\mathrm{min}{=}2$ free
positions.

That floor is a natural requirement rather than a tuned parameter, and
\dSABRE{}~\cite{lidsabre} independently arrives at the same value as its
own routing legality condition. A core with no free physical
qubit is dead: it cannot vacate an occupied communication port by local
SWAPs, so no inter-core action can reach it. A core with exactly one free
position is alive but cannot accept a \TeleData{}, since the arriving
qubit would fill it. Two is therefore the smallest reserve under which
every core can both receive a teleport and remain able to make room
afterwards. $f_\mathrm{min}$ accordingly plays three roles, which we keep
apart: this \emph{initial} condition; the \emph{admission threshold} a
destination must meet \emph{before} a normal \TeleData{}
(Section~\ref{sec:sfc-plan-first}), so at least one position remains
after one; and the threshold defining a \emph{reservoir} for capacity
relief (Section~\ref{sec:sfc-relief}). It is not maintained after every
move: a core admitted at exactly $f_\mathrm{min}$ drops to one free, and
cores do reach one free position during routing.

\textbf{Temporal locality-greedy.} Three steps.
\emph{(i) Weighting}: each CX gate $g=(q_i,q_j)$ contributes
$\gamma^{\mathrm{asap}(g)}$ to the interaction weight $w(q_i,q_j)$, where
$\mathrm{asap}(g)$ is $g$'s as-soon-as-possible layer in the CX-only DAG and
$\gamma{=}0.99$, so early interactions weigh more than late ones while
repeated interactions accumulate. \emph{(ii) Core assignment}: logical
qubits are visited in the order they first appear as a CX operand and
each is placed in the core holding its heaviest already-placed
neighbour when that core has headroom above $f_\mathrm{min}$, falling
back to the core with the most remaining reserved capacity.
\emph{(iii) Physical placement}: within each core, logicals are laid
onto positions by descending interaction weight onto ascending
intra-core centrality, so the most-connected qubits take the most
central slots.

The steps are complementary. The discount co-locates the pairs that
must interact soonest; first-appearance order handles chain-structured
circuits, where a balanced-first-layer rule would scatter the chain
across cores; and the centrality step keeps hub qubits cheap to reach.
Its one weakness is that the $f_\mathrm{min}$ reservation is uniform
across cores, which suits a grid or a ring but not a core graph with a
hub (Section~\ref{sec:heavyhex}).

\subsection{Front Classification}
\label{sec:sfc-classify}

Every front gate is classified under the current layout $\ell$. 1Q
gates are always directly executable; a CX $g=(q_i,q_j)$ with both
operands in core $c$ is \emph{direct-local} if
$\dL(c,\ell(q_i),\ell(q_j))=1$ and \emph{local-needing-SWAP}
otherwise; a CX whose operands lie in different cores is
\emph{adjacent-remote} if those cores are core-graph neighbours and
\emph{non-adjacent-remote} otherwise. Directly executable gates drain
first and completely, intra-core SWAPs are exhausted next, and
remote-stage decisions are taken only once no front gate is
intra-core. A cost guard caps the front at $96$ gates; it binds only on the three
largest QPEexact instances, where removing it leaves the emitted stream
unchanged, since truncation is by ascending gate index and directly
executable gates drain before any routing decision is taken.

\subsection{Intra-Core SWAP Scoring}
\label{sec:sfc-intra}

This stage is \SABRE{}~\cite{li2019tackling}. For a local-needing-SWAP
gate set $F_\mathrm{loc}$, candidate SWAP edges are the coupling-graph
neighbours of every physical position $F_\mathrm{loc}$ touches, and each
is scored under its post-SWAP layout $\ell_a$ by
\begin{equation}
  J(a) = \bar d_{\mathcal{F}}(a) + \lambda_\mathrm{loc}\,\bar d_{\mathcal{E}}(a),
  \qquad \lambda_\mathrm{loc}=0.8,
  \label{eq:sfc-local}
\end{equation}
the mean intra-core distance $\dL(c,\ell_a(q_i),\ell_a(q_j))$ over
$F_\mathrm{loc}$, plus the same mean over an extended set of up to
$N_\mathrm{loc}{=}20$ local CX gates from the next $L_\mathrm{loc}{=}12$
DAG layers. The lowest $J$ is applied; ties break on raw front-layer
distance, then on a constant-seeded generator. Note the sign convention
differs between the two stages: local candidates \emph{minimise}
distance, whereas remote plans \emph{maximise} gain
(Section~\ref{sec:sfc-scoring}).

\subsection{Plan-First Remote Stage}
\label{sec:sfc-plan-first}

\PORTER{} manipulates remote work as \emph{plans}. A plan is a
complete, committable specification of one inter-core action: which
primitive fires, which gate or same-control run it resolves, its
direction, and consequently its \emph{readiness conditions} --- which
logical endpoint must sit adjacent to which communication port, and
which ports must be free. What it deliberately leaves unspecified is
the SWAP sequence that establishes those conditions. Alternatives are
compared at the level of \emph{what} remote work to do next, each
scored as if its preconditions were met; only the committed plan is
handed to the machinery that works out \emph{how}.

Formally, a plan is a tuple
\[
  p \;=\; \bigl(\pi,\; G(p),\; \mathrm{dir},\; c_\mathrm{src},\;
                c_\mathrm{dst},\; \Pi(p),\; \mathrm{ready}(p,\ell)\bigr),
\]
with $\pi\in\{\TeleData{},\TeleGate{},\TeleGatePacket{}\}$ the primitive,
$\mathrm{dir}$ its orientation, $c_\mathrm{src}$ and $c_\mathrm{dst}$ the
cores involved, $\Pi(p)$ the communication ports it reserves, and
$\mathrm{ready}(p,\ell)$ the predicate that holds when $p$ can fire.
$G(p)$ is the set of gates the action \emph{discharges}: for a
\TeleGate{}, the single front CX it executes; for a \TeleGatePacket{},
the run of same-control gates collected in
Section~\ref{sec:sfc-packet}; for a \TeleData{}, the empty set, since
moving a qubit executes no gate --- its value lies entirely in the
gates the relocation makes local, which the scorer estimates
(Section~\ref{sec:sfc-scoring}).

Three quantities are kept distinct: the plan's \emph{utility}, evaluated
under the hypothesis that $\mathrm{ready}(p,\ell)$ holds whether or not
it does; its \emph{readiness cost}, the local work still needed, used
only to break ties; and the \emph{preparation policy} that chooses those
local SWAPs after $p$ is committed. Two design decisions follow:
utility never includes readiness cost, and once a plan is committed
\PORTER{} works only on that plan --- it generates no other plan and
scores no alternative --- until the plan fires or is abandoned because no
preparation SWAP improves its readiness. Section~\ref{sec:related} places
both against the baselines' choices; Section~\ref{sec:ablation} measures
the second.

\textbf{The candidate sets.} When the front holds only remote CX gates,
\PORTER{} builds two sets. \textbf{Normal plans} $\mathcal{P}$ are the
actions that could fire once prepared. For each adjacent-remote CX they
hold a \TeleGate{}; a \TeleGatePacket{} if a same-control run of $\ge 2$
gates can be collected; and, for either endpoint, a \TeleData{} into the
partner's core when that core has $f_\mathrm{min}$ free positions. A
non-adjacent-remote CX cannot be discharged in one action, so it
contributes only \TeleData{} hops that move one endpoint to a neighbouring
core \emph{strictly closer} to the other endpoint's core, again subject to
$f_\mathrm{min}$.

\textbf{Blocked plans} $\mathcal{B}$ are the same \TeleData{} candidates
whose destination fails the $f_\mathrm{min}$ test. \PORTER{} never
commits one --- executing it would drive a core below the floor. It scores
them anyway, as a measurement of what capacity is currently costing:
$\mathcal{B}$ names the cores that are saturated and says how much gain
is being forgone there, which is what the relief tiers of
Section~\ref{sec:sfc-relief} act on.

\textbf{Selection.} Every plan in both sets is scored
(Section~\ref{sec:sfc-scoring}) \emph{before} any preparation SWAP for it
exists. \PORTER{} sorts $\mathcal{P}$ by the key below and walks it in
order, taking the first plan that is either ready or admits an improving
preparation SWAP. A higher-scoring plan that is neither is skipped, not
waited for. Two things can then override that choice, and both are driven
by the single \emph{highest-scoring} member of $\mathcal{B}$, which we
write $b^\ast = \arg\max_{b\in\mathcal{B}} \mathrm{total}(b)$; the rest of
$\mathcal{B}$ enters no comparison.

If a plan $p^\ast$ was found and $\mathrm{total}(b^\ast) -
\mathrm{total}(p^\ast) > m_\mathrm{assist}{=}5.0$, \PORTER{} abandons
$p^\ast$ and relieves the core that blocks $b^\ast$ instead. If no plan in
$\mathcal{P}$ was ready or preparable --- which includes the case
$\mathcal{P}=\emptyset$, but is not limited to it --- it relieves
$\mathcal{B}$'s blocked destinations in ascending hop order. In both cases
what is committed is a relief \TeleData{} generated for the purpose, never
$b^\ast$ itself. Having committed, \PORTER{} applies only that plan's
preparation SWAPs until it is ready, no improving SWAP remains, or the
decision state --- plan, layout, RNG --- repeats, which raises rather than
loops.

\textbf{Preparation SWAPs.}\label{sec:sfc-prep} A committed plan has
exactly two readiness requirements, one per side: source and destination
for \TeleData{}, control and target for \TeleGate{} and
\TeleGatePacket{}, whose target side is routed at execution time
(Section~\ref{sec:sfc-packet}). For each unmet requirement, candidate
SWAPs are the edges incident to the plan's logical endpoint, or to a
nearest free position tied for minimum distance to the relevant port
while that port stays occupied. Each is scored by the post-SWAP
readiness cost, and at most one improving SWAP per side is applied per
pass.

\subsection{Plan Scoring: Direct, Latent, and Lookahead Gain}
\label{sec:sfc-scoring}

Every plan $p$ scores $\mathrm{total}(p) = \mathrm{direct}(p) +
\mathrm{lookahead}(p)$. All kinds share one convention. Write $\kappa$
for the map sending a logical qubit to the core holding it under the
current layout, and $\kappa'$ for the same map under the layout the plan
would produce --- identical to $\kappa$ except that a \TeleData{}'s
moving qubit now sits in $c_\mathrm{dst}$. For a CX $g=(q_i,q_j)$,
\[
  \Delta(g) = \dC\bigl(\kappa(q_i),\kappa(q_j)\bigr)
            - \dC\bigl(\kappa'(q_i),\kappa'(q_j)\bigr)
\]
is the core-graph distance the plan removes from $g$: $1$ for a gate the
move makes local, $0$ for one it does not touch, negative for one it
pushes apart.

A \textbf{\TeleGate{}} scores a constant direct gain of $1$, one remote
CX resolved, with no lookahead. A \textbf{\TeleGatePacket{}} scores the number of remote CX gates in the
collected packet. These are not discounted lookahead: collection returns
a committed executable sequence, and once the cat resource is live every
member executes under it, each target reached by local SWAPs that are
forbidden from touching the two reserved ports
(Section~\ref{sec:sfc-packet}). A \textbf{\TeleData{}} plan executes no gate, so its whole score is an
estimate of the gates its moving qubit $q$ will meet. Three sets of CX
gates on $q$ contribute, found by simulating the DAG frontier forward
under $\kappa'$:
\begin{itemize}[leftmargin=1.2em,itemsep=1pt,topsep=2pt]
\item $D(p)$, the front CX on $q$. Because $q$ has at most one
  zero-predecessor gate at a time, this is the plan's seed gate and
  nothing else, so $\lvert D(p)\rvert = 1$.
\item $L(p)$, the CX gates on $q$ exposed by \emph{local closure}: the
  simulator repeatedly retires every front gate that is executable under
  $\kappa'$ --- one-qubit gates, and CX gates whose operands
  $\kappa'$ places in one core --- and every CX on $q$ that surfaces
  while it can do so joins $L(p)$. Closure stops at the first simulated
  front with nothing locally executable. These are current pressure
  rather than prediction: no gate outside $\kappa'$'s reach was needed to
  expose them, and the teleport fixes their core distance the moment they
  appear.
\item $A_k(p)$, the CX gates on $q$ found by continuing past that
  stopping front, in simulated layer $k \le L_\mathrm{tp}$, discounted by
  $w_k = \max(w_\mathrm{min}, w_0\gamma^{k-1})$ with $w_0{=}0.9$,
  $\gamma{=}0.9$, $w_\mathrm{min}{=}0.5$. These are prediction.
\end{itemize}
Then
\begin{align}
  \mathrm{direct}(p)    &= \!\!\!\sum_{g\in D(p)\cup L(p)}\!\!\!\Delta(g),
    \label{eq:sfc-teleport}\\[-2pt]
  \mathrm{lookahead}(p) &= \sum_{k\ge1}\ \sum_{g\in A_k(p)} w_k\,\Delta(g),
    \nonumber
\end{align}
so $L(p)$ enters at full weight alongside $D(p)$. Alongside the score
\PORTER{} also computes $\mathrm{cap}(p) =
1/\max(1,f_\mathrm{dst}-1)$, which grows as the destination approaches
the capacity floor. It is never added to $\mathrm{total}$; it is carried
separately and used only to break ties, so that between two plans of
equal estimated value the one leaving more room wins.

Preparation cost appears nowhere in $\mathrm{total}$. Plans are ordered
by the lexicographic key
\[
  \bigl(-\mathrm{total},\ \neg\mathrm{ready},\ \mathrm{prep},\
        \mathrm{rank}(\pi),\ \mathrm{cap},\ -\mathrm{lookahead}\bigr),
\]
smallest first, so gain decides first, readiness second, and preparation
cost third; a stable plan identifier resolves anything still tied. The
kind rank prefers \TeleData{} $(0)$ to a packet $(1)$ to a single
\TeleGate{} $(2)$, keeping the layout-changing action when estimated
value, readiness and preparation cost are all equal. Because preparation
cost sits below gain, a plan that is cheap to prepare cannot displace one
that buys more progress --- which is the property that distinguishes this
scorer from \dSABRE{}'s, where staging cost is additive
(Section~\ref{sec:related}). The horizon $L_\mathrm{tp}$ counts \emph{layers}, and at
most one gate on the moving qubit can appear per layer, since a qubit
has at most one zero-predecessor gate at a time. A gate cap
$N_\mathrm{tp}$ therefore cannot bind whenever
$N_\mathrm{tp}\ge L_\mathrm{tp}$, so $L_\mathrm{tp}$ alone governs how
far the estimate looks. It is the one parameter \PORTER{} does not fix
by constant; choosing it is a protocol question, deferred to
Section~\ref{sec:horizon}.

\subsection{Same-Control Packet Collection}
\label{sec:sfc-packet}

Same-control CX gates are chained by DAG dependency edges, so they
never appear in the front together: a packet cannot be read off the
front and must be collected by forward simulation.
From a seed adjacent-remote CX $g=(q_c,q_t)$ with target core $c_t$,
\PORTER{} simulates the DAG frontier forward for up to $120$ layers,
absorbing any front CX that shares control $q_c$ and has its target in
$c_t$ (up to $8$ gates), and any front 1Q gate whose qubit is already in
$c_t$, since those execute freely while the cat resource is live.
Collection stops at the first unproductive layer or at the size cap. The
window counts simulated layers, not collected CXs, so it acts as a cost
guard rather than a tuning knob. Because the simulation reaches past the
current front, a packet may contain gates a front-limited scan could not.
Collection is a heuristic in one respect we have not ablated: stopping at
the first unproductive layer can miss a profitable packet separated by
harmless intervening work.

Collection only \emph{discovers} the run; nothing is emitted while it
simulates. The sequence it returns is recorded on the plan, and if that
plan is committed the sequence is emitted in exactly that order --- one
\texttt{cat\_entangler}, which consumes the packet's single EPR pair;
one \texttt{cat\_cx} per member, each target first brought beside the
port by ordinary local SWAPs that may not touch either live port; and one
closing \texttt{cat\_disentangler}, which frees both ports. Fixing the
order at collection time is what lets the scorer count every member as
work the packet will actually do: the members are DAG-chained, so
executing them in that order respects their dependencies, and no member
can become unexecutable once the resource is live.

\subsection{Capacity Relief}
\label{sec:sfc-relief}

Both tiers answer the same question --- some core $c$ is at or below
$f_\mathrm{min}$ and a \TeleData{} wants to enter it --- by moving a
qubit \emph{out} of the congested region rather than into it. Neither
picks a destination freely: a breadth-first search from $c$ over the core
graph finds the nearest \emph{reservoir}, a core with at least
$f_\mathrm{min}$ free positions, and the relief action moves one qubit
from the penultimate core of that path into the reservoir at the end of
it. Every logical qubit in the penultimate core is a candidate, and the
candidates are scored and ordered by the plan machinery already
described, grouped by hop count so that shorter paths are tried first.
Chaining beyond one hop is optional and enabled by default, which lets
relief propagate along a path when the immediate neighbour is itself
full.

The two tiers differ only in when they fire. \textbf{Tail relief} fires
reactively, when $\mathcal{P}$ is empty and the front is starved.
\textbf{Opportunistic relief} fires pre-emptively, while a normal plan is
still available, whenever a blocked plan out-scores it by more than
$m_\mathrm{assist}$ --- the judgement being that clearing the congestion
now is worth more than taking the best currently legal action.

\subsection{Progress and the Failure Model}
\label{sec:sfc-progress}

Deterministic greedy routing on a capacity-constrained machine can
stall, and \PORTER{} layers four defences against that. It keeps capacity
away from zero: a core with no free physical qubit is terminal, since it
cannot vacate an occupied port by local SWAPs, so \PORTER{} legalises the
entry layout and admits a \TeleData{} into $c$ only while
$\mathrm{free}(c)\ge f_\mathrm{min}$ --- routing therefore cannot create
a terminal core, and an external layout that already contains one is
reported as infeasible. It detects starvation rather than thrashing, an
empty $\mathcal{P}$ beside a non-empty $\mathcal{B}$ naming the cores
responsible; it manufactures capacity, tail relief turning that signal
into work (Section~\ref{sec:sfc-relief}); and it bounds every loop, never
selecting a plan side of infinite preparation cost, hashing its decision
state once per preparation round and raising if it repeats, and capping
the loops with two budgets. Together these make every returned route
correct and every run terminating, but they do not guarantee that a run
terminates in success; Section~\ref{sec:related} states the three
guarantees precisely and places \PORTER{} against \dSABRE{}, which does
carry such a guarantee. A per-iteration cost analysis of the loop is in
\appComplexity{}.
