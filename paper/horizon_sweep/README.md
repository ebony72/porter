# Horizon grid: fixed-horizon sweep and weight-floor factorial (2026-09-03)

Data behind `paper/horizon_open_question.md`'s sweep and the evaluation of the
vault note `porter_adaptive_horizon_experiment_instructions.md`
(evaluation: vault `porter_adaptive_horizon_experiment_evaluation.md`).

* `horizon_grid.jsonl` / `horizon_grid.csv` -- 3,120 single forward passes
  (`selection=False`, PORTER's own deterministic layout, 300 s SIGALRM guard,
  every completed route replay-verified): all 48 instances x
  {4,8,16,32,64,128} x ten lookahead weight schedules, plus {48,256} for the
  shipped one and {256} for the slow-decay ones.  Schedules are (w_min, gamma):
  `base` (0.5, 0.9) = shipped, `floor0` (0, 0.9), `floor25` (0.25, 0.9),
  `flat` (0.9, 0.9) = no decay, `slow95` (0, 0.95), `slow97` (0, 0.97),
  `slow99` (0, 0.99), and a gamma sweep at the shipped floor `g85` (0.5, 0.85),
  `g95` (0.5, 0.95), `g99` (0.5, 0.99).  `status` is completed / timeout /
  livelock.
* `timeout_reruns.jsonl` -- seven timed-out cells re-run at a 900 s guard with a
  progress trace on the single gate-retirement point.
* `guard_validation.jsonl` -- the stall guard checked on all 48 instances under
  the shipped protocol (`hz_guard_validate.py`): op-stream SHA, EPR, SWAPs,
  depth, tie count and the selected horizon, guard off against guard on.
* `gate_budget_sweep.json` -- the refuted per-qubit gate budget
  (`teleport_lookahead_cx_count` k in {16..64} with `dag_extended_max_layers`
  512); `paper/horizon_open_question.md` cites this as `phase2.json`.
* `refine_fixed_horizon_{main,rest}.json` -- backward refinement at the FIXED
  default horizon (`selection=False`, 5 passes), isolating what refinement
  contributes without horizon selection beneath it.  Not the shipped `+R`.
* `budget_probe.jsonl`, `portfolio_head.jsonl`, `budget_validation.jsonl` --
  the deterministic work budget (`hz_budget.py`) and the 3x3 portfolio's cost
  re-measured against HEAD (`hz_portfolio.py`, `hz_budget_validate.py`).
  `hz_head.py` is `hz_common.py` pointed at the repo rather than the frozen
  snapshot, for measurements that must include the stall guard.
* `optimisation_ablation.jsonl` -- each of the four cost optimisations toggled
  independently over all 48 instances in one process (`hz_ablate_opt.py`), so
  the times are comparable with each other; every configuration emits the
  identical op stream, which is the point.
* `four_horizon_cells.jsonl`, `four_horizon_refined.jsonl` -- every horizon in
  {4,8,16,32,48,64,128} at the shipped weight schedule on all 48 instances, and
  PORTER+R over two candidate four-value sets (`hz_four.py`).  This is the
  evidence for replacing the density branch with one fixed set.
* `portfolio_refined.jsonl` -- PORTER+R over a (schedule, horizon) portfolio
  (`hz_portfolio_r.py`), the appendix-only result.
* `stall_gaps.json` -- longest run of router iterations retiring no gate, for
  all 48 instances at L=16 and L=128; the basis for the stall-guard threshold.
* `sweep_2026-09-01_*.json` -- the earlier sweep under the OLD six-term
  selection key (348 routes).  24 of 271 jointly completed cells differ from
  the `base` arm; 3 at the 3-route protocol.
* `MANIFEST.txt` -- commit + hashes of the frozen working tree the grid was
  routed from (HEAD 53200e9 plus the uncommitted three-term selection key).
* `report_*.md` -- generated by `hz_offline.py` (Phase 0/1/2), `hz_floor.py`
  (Phase 6), `hz_slow.py` (the slow-decay test and the fourth-route result) and
  `hz_joint.py` (single-set portfolios over (schedule, horizon) routes, which
  is what would replace the rho branch).
* `hz_common.py`, `hz_run.py` -- loader and harness (runs against the repo
  root when no `snap/` directory is present).
* `scale_cells.jsonl` -- the lookahead-scaling sweep (`hz_scale.py`): all 48
  instances x 7 horizons under `teleport_lookahead_scaling="sqrt"`, every
  completed route replay-verified.  The shipped `sum` arm to compare it
  against is `horizon_grid.jsonl`'s `base`.
* `freeze_modes.jsonl` -- every non-completing cell of that `base` arm re-run
  with the stall guard on and traced (`hz_freeze.py`), classified as a
  teleport shuttle, a local-SWAP cycle or neither.
* `revisit_cells.jsonl`, `revisit_healthy16.jsonl` -- `hz_revisit.py` with and
  without `teleport_revisit_block`, on the cells the shipped scorer fails and
  on every instance at the configured horizon.  The second file carries op-
  stream hashes, so it is the control for whether the flag perturbs a healthy
  route.
* `domination.jsonl` -- per-instance |lookahead| / |direct| over every scored
  teleport candidate at L=16, plus how often the lookahead flips the winner
  (`hz_ratio.py`).  Tested as a runtime predictor of whether a deeper horizon
  pays; it is not one.
* `depth_features.json` -- static DAG features per instance (`hz_depth.py`):
  gates reachable and distinct partners seen within each horizon.
* `report_scale.py`, `report_revisit.py` -- regenerate the tables in
  `report_lookahead_scale.md`, which is the write-up for all of the above.
* `horizon_second_job.html` -- source of the artifact summarising that report
  (https://claude.ai/code/artifact/a47fd707-40f4-44be-b753-752dde8789c2), the
  same way `horizon_sweep.html` is the source of the earlier one.  It is the
  page as authored; the platform supplies the surrounding `<head>`.

Nothing here is read by `verify_paper_numbers.py`; the paper's released
numbers are untouched.
